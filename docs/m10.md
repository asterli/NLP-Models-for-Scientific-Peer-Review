# M10 / F04: prompted claim-extraction baseline (frozen)

- **Status:** frozen. Prompt **v2** (per-sentence labeling) is the prompted baseline for M12/F06.
- **Model:** Qwen2.5-7B-Instruct, untuned, greedy decoding. Same base model as M11.
- **Code:** `scripts/baseline_claims.py --split dev --prompt v2`; batch runner `scripts/slurm/m10_dev.sbatch`.
- **Tuning data:** the frozen M08 dev split only (3 papers, 80 sentences, 18 CLAIM). Test untouched.

## Prompt variants (all on dev)

| prompt | idea | P | R | F1 | predicted / gold claims |
|---|---|---:|---:|---:|---|
| v1 | zero-shot, return a JSON list of CLAIM sentence IDs (Oct 18 run) | 0.71 | 0.28 | 0.40 | 7 / 18 |
| **v2** | label **every** sentence `sXXX: CLAIM|BACKGROUND`, prompt restates the M06 decision procedure | **0.79** | **0.61** | **0.69** | 14 / 18 |
| v3 | v2 + "feasibility/pilot outcomes are findings" clause | 0.23 | 1.00 | 0.37 | 80 / 18 |

- v1's low recall comes from the output format: asked for a list, the model returns 2–4 IDs per paper regardless of length.
- v2 forces a decision per sentence; recall more than doubles and precision also rises.
- v3 is a negative result: the extra clause tipped the model into labeling all 80 sentences CLAIM. Kept in the code for reproducibility, not used.

The v1 dev numbers are a re-score of the Oct 18 all-paper predictions restricted to dev papers; rerunning v1 on dev reproduces them exactly (`results/m10_dev_v1.json`).

## v2 error inspection (all 10 dev errors)

**7 misses (gold CLAIM → predicted BACKGROUND).** Six are from one paper, a feasibility trial (CTI for people leaving prison): recruitment rate, retention rate, fidelity, acceptability, cost/data-collection feasibility. The model reads these feasibility outcomes as study-setup descriptions (M06 rule C) rather than the paper's findings. The seventh (`s017`, a statement about funding policy) is borderline under the guide.

**3 false positives (gold BACKGROUND → predicted CLAIM).**
- `s001` "To evaluate healthcare cost and utilization changes among …" and `s023` "Our primary objective was to assess …" are stated research objectives, which M06 §3 step 1 labels CLAIM. These look like annotation errors in the dev gold; flagged for the label owners. They cap achievable dev precision at ~0.86.
- `s018` ("… will be of substantial interest to DV agencies …") is an implication sentence; defensible either way.

Caveat: the feasibility pattern is one dev paper, not evidence of a general pattern (F04 note).

## Frozen settings

- Prompt: `PROMPTS["v2"]` in `scripts/baseline_claims.py` (byte-identical copy in `src/claims/prompting.py::SYSTEM_V2`, which M11 trains on).
- Decoding: greedy, `max_new_tokens=700`.
- Parsing: regex `sXXX: CLAIM` lines, restricted to the paper's sentence IDs, deduplicated.
- Input: `data/papers/papers.jsonl` sentences with section tags; split membership from `data/claims/splits/*.jsonl`.

## Artifacts

- Predictions: `data/claims/predictions/baseline_qwen7b_dev_{v1,v2,v3}.jsonl` (shared Claim schema).
- Scores: `results/m10_dev_{v1,v2,v3}.json` (from `scripts/score_predictions.py claims`).
- Raw model text: `/project2/xiangren_1987/group_40/runs/m10_dev_{v1,v2,v3}_raw.jsonl` (outside the repo).
- Oct 18 zero-shot run over all 20 papers: `data/claims/predictions/baseline_qwen7b.jsonl` (untuned reference, kept).

## Reproduce

    sbatch scripts/slurm/m10_dev.sbatch                 # v1 and v2 on dev, scored
    PROMPTS="v3" sbatch scripts/slurm/m10_dev.sbatch    # any subset of variants

Or interactively on a GPU node (env + `HF_HOME` as in `docs/m09.md`):

    python scripts/baseline_claims.py --split dev --prompt v2 --out data/claims/predictions/baseline_qwen7b_dev_v2.jsonl
    python scripts/score_predictions.py claims --pred data/claims/predictions/baseline_qwen7b_dev_v2.jsonl \
        --gold data/claims/splits/dev.jsonl --out results/m10_dev_v2.json

## Hand-off to M12 / F06

Run `--prompt v2 --split test` exactly once, after M11 settings are frozen, and score with the same command against `data/claims/splits/test.jsonl`. Baseline and fine-tuned model share input format, parser and scorer.
