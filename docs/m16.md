# M16 — Freeze the Classifier-Data Splits

## Goal

Freeze the train, development, and test splits for the novelty/overlap classifier.

The classifier data comes from the labeled comparison dataset produced in M15. Splits are assigned at the **source-paper level** rather than randomly at the individual comparison level to reduce data leakage between train, development, and test sets.

Where an M15 source paper was already included in M08, its finalized M08 split assignment was preserved. Additional source papers introduced through the M14/M15 candidate-retrieval process were assigned at the paper level while checking for related-paper and claim leakage.

## Input Data

M16 uses:

- The finalized M15 labeled comparison dataset.
- The retrieval candidate pool used during M14/M15.
- The finalized M08 source-paper split assignments.

The M15 dataset contains 75 labeled comparisons with three possible labels:

- `Distinct`
- `Overlapping`
- `Insufficient evidence`

For the initial binary classifier, only `Distinct` and `Overlapping` examples are included. `Insufficient evidence` examples are excluded from the initial training data.

## Split Procedure

### 1. Preserve M08 assignments

If the source paper for an M15 comparison was already present in M08, the M08 train/development/test assignment was reused without modification.

This ensures that the claim-extraction and novelty-classification datasets do not independently assign the same source paper to different splits.

### 2. Assign additional source papers

M14/M15 retrieved candidate papers beyond the original M08 corpus. These papers therefore did not have existing M08 assignments.

Additional papers were assigned at the **source-paper level**, not at the comparison level. All comparisons originating from the same source paper remain in the same split.

Related papers using the same underlying study/trial data were also kept together where identified. In particular, papers associated with the At Home/Chez Soi trial were not allowed to cross split boundaries.

### 3. Remove unresolved examples

The 10 comparisons labeled `Insufficient evidence` were excluded from the initial binary classifier dataset.

These examples are retained in the original M15 dataset for audit purposes but are not included in the M16 v1 train, development, or test files.

This leaves 65 binary examples.

### 4. Check for comparison leakage

Before freezing the splits, the binary dataset was checked for:

- exact duplicate comparisons;
- reversed duplicate comparisons;
- repeated source papers across different splits; and
- near-duplicate claim text crossing split boundaries.

No exact or reversed duplicate comparisons were found in the final binary dataset.

A cross-split near-duplicate check using a similarity threshold of 0.80 also found no near-duplicate claim texts crossing the final train/development/test boundaries.

## Frozen Files

The versioned M16 classifier files are:

```text
data/novelty/
├── M16_split_v1.xlsx
└── splits/
    ├── train_v1.jsonl
    ├── dev_v1.jsonl
    └── test_v1.jsonl
```

`M16_split_v1.xlsx` records the source-paper assignments and provides an audit trail for how the M16 splits were constructed.

The JSONL files are the frozen classifier datasets that should be consumed by downstream training and evaluation scripts.

## Rules for Downstream Work

The M16 v1 splits are considered frozen.

Downstream experiments should:

1. Train models using `train_v1.jsonl`.
2. Use `dev_v1.jsonl` for model selection, tuning, and development-time evaluation.
3. Keep `test_v1.jsonl` untouched during training and tuning.
4. Use the test set only for final evaluation.
5. Never randomly re-split the individual M16 comparisons.
6. If new data is added later, create a new version of the split files rather than modifying the v1 files in place.

Any future additions should continue to use source-paper-level assignments and should be checked for related-paper, duplicate-comparison, and near-duplicate claim leakage before being added.
