# M12 / F06: held-out test evaluation of the claim extractor

- **Status:** test evaluation done, run once (job 13919066, code at `9eda952`). Callable extractor written; its GPU check is `scripts/slurm/m12_extractor_check.sbatch`.
- **Setup:** M10 prompted baseline (prompt v2) vs M11 fine-tuned LoRA adapter (`r16_lr2e-4_s544/best`). Both frozen on dev before test was touched. Test = 3 papers, 120 sentences, 26 CLAIM.

## Results on test

| system | P | R | F1 |
|---|---:|---:|---:|
| Prompted baseline v2, as frozen | 0.33 | 0.12 | 0.17 |
| Fine-tuned LoRA | 0.88 | 0.85 | 0.86 |
| *Post-hoc:* baseline with `RESULTS`/`CONCLUSIONS`/`OBJECTIVE` read as CLAIM | 0.78 | 0.96 | 0.86 |

Dev F1 for reference: 0.69 (baseline), 0.87 (fine-tuned).

## Why the baseline dropped

- It labeled every test sentence, but for 35 of 120 it wrote its own section-style labels (`RESULTS`, `CONCLUSIONS`, `OBJECTIVE`, `METHODS`) instead of `CLAIM`/`BACKGROUND`. The frozen parser counts only `CLAIM`.
- 22 of its 23 missed claims were labeled `RESULTS` (13), `CONCLUSIONS` (6) or `OBJECTIVE` (3). Only one was called `BACKGROUND`.
- This did not happen on dev (all 80 sentences got a valid label), so it could not be caught before freezing.
- The post-hoc row is computed from the saved output after seeing test labels. It is optimistic and is not the baseline's score. It shows that the gap is mostly output format, not claim judgment: fine-tuning bought reliable format and higher precision at lower recall.

## Fine-tuned errors (all 7)

- **4 misses:** three study-aim sentences in `jamanetworkopen.2021.38464` (`s002`, `s029`, `s030`); one cited discussion sentence in `jamanetworkopen.2026.16300` (`s026`).
- **3 false positives:** two study-aim sentences in `jamanetworkopen.2026.16300` (`s003`, `s044`); one sample description in `29767342261444527` (`s010`).
- **Pattern:** 5 of 7 are aim sentences, which the gold labels mark CLAIM in one paper and BACKGROUND in another (also in dev, see `docs/m10.md`). The model cannot match both.

## Limitations

- 3 test papers, 26 claims: one sentence is about 4 points of recall.
- One configuration and one adapter were tested; aim-sentence labels are inconsistent in the gold data.

## Callable extractor (hand-off to the pipeline)

    from claims.extractor import ClaimExtractor            # src/ on sys.path
    extractor = ClaimExtractor("/project2/xiangren_1987/group_40/runs/m11/r16_lr2e-4_s544/best")
    claims = extractor.extract(paper)                      # Paper record in, Claim records out

- Input: a Paper record (`paper_id`, `title`, `sentences` with `sentence_id`, `section`, `text`). Output: Claim records with the original sentence text and IDs; `[]` if there are no sentences or no claims.
- Same prompt, decoding and parser as the test run. Needs a GPU; load once, call per paper.
- `extractor.last_unlabeled` lists sentences the model gave no valid label (treated as not claims).
- `scripts/check_extractor.py` checks on a GPU that it reproduces the committed dev predictions. No-GPU tests: `tests/test_claim_extractor.py`.
